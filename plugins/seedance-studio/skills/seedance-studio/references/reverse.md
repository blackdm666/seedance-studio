# 视频反推提示词（证据优先 · 六段可视化流水线）

把一条参考视频拆解为可直接提交 Seedance 2.5 的提示词。方法论核心：**只写有帧证据的内容**，禁止把合理想象写成事实。

**为什么要六段而不是"抽几帧看看就写"**：纯抽帧只能看到一个个孤立的静止画面——人物是往前走还是后退、镜头是推近还是人物走近、手是拿起还是放下，单帧全都分不清。所以在"看帧"之前先加一道**运动理解 pass**（真深度图视频 / 运动热图），把人物动作与前后景关系、镜头运动变成肉眼可读的东西，再判运镜、写分镜、收敛提示词。**每一段都落盘产物、逐段展示给用户**——这正是本插件相对"随便反推一下"的能力差距。

## 各段与工具分工（先看清谁干什么）

| 段 | 产物 | 主力工具 | 谁来判断 |
|---|---|---|---|
| ① 探测 | 元数据（时长/分辨率/帧率/音轨） | **ffprobe** | 脚本 |
| ② 结构总览 | 联系表 sheet、切镜候选点、密集帧 | **ffmpeg** | 脚本抽帧，Claude 读 |
| ③ 运动理解 | 深度图视频（灰度/熔岩/光谱）+ 四格样张；无 torch 时降级为运动热图 | **Depth-Anything V2（深度大脑）+ ffmpeg（上色/合成）** | 脚本产出 |
| ④ 运镜判定 | 运镜清单（推拉摇移升降/跟随/机位） | Claude 亲眼读 ②③ 帧 | **Claude** |
| ⑤ 分镜头脚本 | 分镜表（时间段×画面×动作×运镜×声音） | Claude | **Claude** |
| ⑥ 最终提示词 | 可直接提交的四层提示词 | Claude | **Claude** |

一句话记住 FF 的位置：**ffprobe 只做①探测，ffmpeg 做②抽帧与③的上色/合成"搬运层"，③的深度理解交给 Depth-Anything，④⑤⑥的判断永远是 Claude 亲眼看帧写出来的。** ffmpeg 不做真深度——亮度伪彩不等于深度。

---

## ① 探测（ffprobe）

```powershell
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate,codec_type -of default=noprint_wrappers=1 "<视频>"
```

记录总时长、分辨率（推断比例）、帧率、是否有音轨。据此定 ② 的抽帧密度与 ③ 的深度 `--fps`。

## ② 结构总览（ffmpeg 抽帧）

```powershell
# 1. 全片联系表：每秒 1 帧拼成网格，先建立整体印象
ffmpeg -y -i "<视频>" -vf "fps=1,scale=480:-1,tile=6x5" -frames:v 1 frames/sheet_%02d.png

# 2. 切镜候选点：场景变化检测（阈值 0.15，偏低以免漏掉同机位跳剪）
ffmpeg -i "<视频>" -vf "select='gt(scene,0.15)',showinfo" -f null - 2>&1 | findstr pts_time

# 3. 对快速动作/模糊转场段落做密集帧（每秒 8 帧）
ffmpeg -y -ss <起点秒> -t <时长> -i "<视频>" -vf "fps=8,scale=640:-1" frames/dense_%03d.png
```

先用联系表建立整体印象、定位镜头切换点，再对每个动作段做密集帧。**这一步只建立"发生了什么"的骨架，动作方向的最终判读放到 ③④ 之后。**

## ③ 运动理解 pass —— 深度图视频（核心增量，务必展示给用户）

把原视频转成**深度图视频**（类似热成像：近处亮/暖、远处暗/冷），人物的身体朝向、肢体前后、与背景的层次一眼可读；再配一张四格样张直观对照。**用插件内置命令一步produce**：

```powershell
node "<PLUGIN_ROOT>/scripts/studio.mjs" depth --video "<视频>" --fps 4 --out "<project>/analysis/depth"
```

产出（落盘、可逐帧看、可直接展示）：
- `depth/f*****.png` —— 每帧真深度灰度图（Depth-Anything V2 单目深度，近=亮）
- `depth_gray.mp4` —— **灰度**深度视频
- `depth_magma.mp4` —— **熔岩伪彩**（magma）深度视频
- `depth_spectral.mp4` —— **光谱伪彩**（turbo）深度视频
- `depth_montage.png` —— **四格样张：原帧 ｜ 灰度 ｜ 熔岩 ｜ 光谱**（先给用户看这张，最直观）

参数：`--fps`（默认 4，越高越平滑越慢）、`--colormap all|gray|magma|turbo`（默认 all 三色全出）、`--model`（默认 `Depth-Anything-V2-Small-hf`，CPU 约 0.6s/帧）、`--py`（指定 python 解释器）。

**读法**：翻 `depth_*.mp4` / 逐帧读 `depth/*.png`——
- 人物**身体朝向与肢体前后**（哪条手臂在前、是侧身还是正对镜头）在灰度/伪彩上比原图清楚得多；
- **前景 vs 背景层次**（人物离镜头多近、背景纵深多深）决定该写"浅景深特写"还是"大景深全景"；
- **深度整体变化**（画面越来越亮=整体逼近镜头=推镜或人物走近；亮块横移=横移运镜/跟随）为 ④ 提供运镜证据。

> **降级**：机器无 Python/torch/transformers 时，`depth` 命令自动回退 **ffmpeg 运动 pass**——`motion_edge.mp4`（边缘轮廓，读姿态）+ `motion_heat.mp4`（帧差热图，读运镜/跟随）。不是真深度，但同样把"动"变得可读。要装真深度：`pip install transformers timm pillow torch`（CPU 版即可）。
> **合规**：深度图仅用于**理解运动**，绝不把原片人物抽帧/抽脸复用——复刻阶段人物一律用 gpt-image-2 生成新身份（见 replicate.md）。

## ④ 运镜判定（Claude 亲眼读 ②③ 帧）

结合 ② 的密集帧与 ③ 的深度/运动视频，逐段判定运镜，每条都要有帧证据：

- **推/拉**：主体在画面里持续变大/变小，且深度图整体变亮/变暗 → 推近 / 拉远。
- **摇/移（pan/track）**：背景横向或纵向连续位移，主体相对稳定 → 摇镜 / 平移 / 跟随（帧差热图上表现为整幅位移）。
- **升降/环绕**：地平线高度变化 / 主体侧面逐渐转出 → 升降臂 / 环绕。
- **机位与景别**：由深度层次判断景别（大特写/特写/中景/全景）与景深（浅/深）。

单帧无法区分"推镜"还是"人物走近"——**必须看连续帧 + 深度整体趋势**共同定论。判不准的运镜标"不确定"，不硬写。

## ⑤ 分镜头脚本（Claude）

把 ①–④ 的证据汇成一张分镜表（这是 shotlist.json 的人类可读版），每段一行：

```text
镜1  0–3秒  景别/机位  运镜  画面与主体动作(起→止)  声音  画面文字
镜2  3–8秒  ……
```

**证据分级铁律**（贯穿④⑤）：
- 每条观察分 `已确认`（帧证据）/ `推断`（合理但无直接证据，标注）/ `未知`（不写入）。
- **开头钩子完整盘点**：前 3 秒的前景动作、背景动作、运镜、画面文字、音乐节奏全部覆盖，不得只留主体动作。
- **画面文字**：准确内容、语言、颜色、位置、出现/持续时间、固定还是随物运动；辨不清标"不确定"。
- 同一卖点下多个快速硬切合并为一个分镜，但保留内部切换顺序。
- 用户纠正后：清空旧判断、重看原始帧与深度图，不得只给旧结论换说法。

## ⑥ 最终提示词（Claude）

先列参考图上传顺序与各自职责（若用户提供了产品/人物图），再输出一份可直接复制的四层提示词：

```text
【全局设定】视频参数、画面风格、核心运镜、整体声音分布（紧凑，只写生成所需）
【主体一致性】只锁定反复出现的核心人物/产品
【场景一致性】只锁定反复出现的核心场景
【文字】已确认的画面文字及其样式、位置、时间
【负面约束】只保留高风险项（主体漂移、文字乱码、钩子缺失）

0–3秒：镜头描写 / 画面与动作 / 声音
3–8秒：……
```

分镜时间用整数。交付前逐项核对：钩子每个成分已写入、**运镜与④的判定一致**、动作方向与帧一致、每个音效有证据、每张参考图只有一个职责。

## 音频（如有，在②之后任意时点）

```powershell
ffmpeg -y -i "<视频>" -vn -acodec libmp3lame audio.mp3
```

口播内容让用户确认或提供文案；无法确认的台词标"不确定"，不编造。**画面出现某动作不代表存在对应音效**——只写确认存在的声音。**背景音乐一律不提取、不复用（版权）**，只在提示词里描述"节奏/情绪"。
