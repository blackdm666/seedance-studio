# 视频反推提示词（证据优先 · 六段可视化流水线）

把一条参考视频拆解为可提交给用户所选视频模型的提示词。方法论核心：**只写有帧证据的内容**，并在出片前按实时目录裁剪到所选模型真正支持的能力。

**为什么要六段而不是"抽几帧看看就写"**：纯抽帧只能看到一个个孤立的静止画面——人物是往前走还是后退、镜头是推近还是人物走近、手是拿起还是放下，单帧全都分不清。所以在"看帧"之前先加一道**运动理解 pass**，把动作、镜头运动、前后景关系变成肉眼可读的东西，再判运镜、写分镜、收敛提示词。**但这道 pass 要按题材选武器**：人物/产品片用**真深度图**（身体朝向、肢体前后一眼可读）；宏大风景/山河/大场面片用**运动热图 + 原帧光色**（深度对天空/云海/水面失效，还会把风景最要命的光线色调大气全抹掉）。**每一段都落盘产物、逐段展示给用户**——这正是本插件相对"随便反推一下"的能力差距。

## 各段与工具分工（先看清谁干什么）

| 段 | 产物 | 主力工具 | 谁来判断 |
|---|---|---|---|
| ① 探测 | 元数据（时长/分辨率/帧率/音轨） | **ffprobe** | 脚本 |
| ② 结构总览 | 联系表 sheet、切镜候选点、密集帧 | **ffmpeg** | 脚本抽帧，Claude 读 |
| ③ 运动理解 | **按题材自适应**：人物/产品→深度图；风景→运动热图+大气样张；武打→多人骨架+运动+深度 | **Depth-Anything V2 / YOLO-pose / ffmpeg** | 脚本产出 |
| ④ 运镜判定 | 运镜清单（推拉摇移升降/跟随/机位） | Claude 亲眼读 ②③ 帧 | **Claude** |
| ⑤ 分镜头脚本 | 分镜表（时间段×画面×动作×运镜×声音） | Claude | **Claude** |
| ⑥ 最终提示词 | 可直接提交的四层提示词 | Claude | **Claude** |
| ⑦ 音频拆解 | 台词时间线 / BGM风格 / 音效时间轴（audio_analysis.md） | **ffmpeg + Gemini 多模态** | 脚本抽音+模型拆，Claude 核对 |

一句话记住 FF 的位置：**ffprobe 只做①探测，ffmpeg 做②抽帧与③的上色/合成/运动"搬运层"，③的深度理解交给 Depth-Anything（风景模式则不用深度、直接用 ffmpeg 运动热图+原帧），④⑤⑥的判断永远是 Claude 亲眼看帧写出来的。** ffmpeg 不做真深度——亮度伪彩不等于深度。

---

## ① 探测（ffprobe）

```powershell
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate,codec_type -of default=noprint_wrappers=1 "<视频>"
```

记录总时长、分辨率（推断比例）、帧率、是否有音轨。据此定 ② 的抽帧密度与 ③ 的深度 `--fps`。

## ② 结构总览（ffmpeg 抽帧）

```powershell
# 1. 全片联系表：每秒 1 帧拼成网格，先建立整体印象
ffmpeg -y -i "<视频>" -vf "fps=1,scale=480:-1,tile=6x5" -frames:v 1 frames/sheet_%02d.png

# 2. 切镜候选点：场景变化检测（阈值 0.15，偏低以免漏掉同机位跳剪）
ffmpeg -i "<视频>" -vf "select='gt(scene,0.15)',showinfo" -f null - 2>&1 | findstr pts_time

# 3. 对快速动作/模糊转场段落做密集帧（每秒 8 帧）
ffmpeg -y -ss <起点秒> -t <时长> -i "<视频>" -vf "fps=8,scale=640:-1" frames/dense_%03d.png
```

先用联系表建立整体印象、定位镜头切换点，再对每个动作段做密集帧。**这一步只建立"发生了什么"的骨架，动作方向的最终判读放到 ③④ 之后。**

## ③ 运动理解 pass —— 按题材选武器（核心增量，务必展示给用户）

**先判题材，再选 pass。** 命令用 `--mode` 切换，判不准就用 `auto`（两种都出、亲眼挑）：

```powershell
# 人物/模特/产品片（有硬几何、要看身体朝向与前后景）→ 深度为主
node "<PLUGIN_ROOT>/scripts/studio.mjs" depth --video "<视频>" --mode character --fps 4 --out "<project>/analysis"
# 宏大风景/山河/云海/建筑空镜（无人物或人物只是比例点）→ 运动+原帧为主，跳过深度
node "<PLUGIN_ROOT>/scripts/studio.mjs" depth --video "<视频>" --mode landscape --fps 2 --out "<project>/analysis"
# 武打/舞蹈/快速动作（招式在零点几秒内）→ 多人骨架 + 运动 + 深度，高帧率
node "<PLUGIN_ROOT>/scripts/studio.mjs" depth --video "<视频>" --mode action --fps 8 --out "<project>/analysis"
# 拿不准 → 两种都出，读帧自己挑（默认）
node "<PLUGIN_ROOT>/scripts/studio.mjs" depth --video "<视频>" --mode auto --out "<project>/analysis"
```

**怎么判题材**：看 ② 的联系表——画面主角是**人/模特/产品/动物**（有清晰前景主体、要看动作与朝向）走 `character`；主角是**山河/云海/城市天际线/建筑空镜/大气氛围**（主体是空间与光，人物缺席或只是渺小比例点）走 `landscape`；**打斗/武打/舞蹈/体育等快速肢体动作**（要逐招看肢体轨迹、两人相对站位）走 `action`；混合片（人物在宏大场景里演）用 `auto`。

### A. character 模式 —— 真深度图视频

把原视频转成**深度图视频**（类似热成像：近处亮/暖、远处暗/冷），人物的身体朝向、肢体前后、与背景的层次一眼可读；配一张四格样张直观对照。产出：
- `depth/f*****.png` —— 每帧真深度灰度图（Depth-Anything V2 单目深度，近=亮）
- `depth_gray.mp4` / `depth_magma.mp4` / `depth_spectral.mp4` —— 灰度 / 熔岩 / 光谱伪彩深度视频
- `depth_montage.png` —— **四格样张：原帧 ｜ 灰度 ｜ 熔岩 ｜ 光谱**（先给用户看这张）
- `motion_edge.mp4` / `motion_heat.mp4` —— 运动 pass 也一并出，补判运镜

**读法**：人物**身体朝向与肢体前后**（哪条手臂在前、侧身还是正对）、**前景 vs 背景层次**（决定浅景深特写还是大景深全景）、**深度整体变化**（越来越亮=推近/走近；亮块横移=横移/跟随）为 ④ 提供运镜证据。

### B. landscape 模式 —— 运动热图 + 大气样张（跳过深度）

**为什么风景不走深度**：单目深度对**天空/云海/水面/雾**这类无纹理区域会糊成一团（把云海压成一片灰渐变），而且深度图会**丢掉光线、色调、大气透视**——恰恰是宏大风景最要命的信息。风景的纵深本来就写在 RGB 里（近实远虚、近暖远冷），运镜靠的是**视差**。所以风景片：
- `atmosphere.png` —— **三帧原图横拼**：读光线/色调/大气透视/构图（**风景反推的头号证据，先看这张**）
- `motion_heat.mp4` —— 帧差热图：**近景视差大=亮、远景/天空视差小=暗**，直接读出推/摇/移/环绕
- `motion_edge.mp4` —— 边缘轮廓：读地平线、建筑轮廓、构图引导线

**读法**：主看原帧（光色大气）+ motion_heat（运镜视差）。**注意**：帧差会把**硬切**也点亮——montage 片切镜密集时，只在**同一镜头内**（用 ② 的切镜点）读运镜，别跨切误判成"猛推"。要临时看一眼深度做层次确认，加 `--with-depth`。

### C. action 模式 —— 多人骨架 + 运动 + 深度（武打/快速动作）

打斗一拳一腿都在零点几秒内，低帧率会漏招——所以 action 默认 **8fps 抽帧**，并加一道**多人骨架 pass**（YOLO-pose，能同时框住两名对打者，各给一种颜色）。产出：
- `pose_strip.png` —— **招式条：等距 5 帧纯骨架横拼**，一眼看 蓄力→出招→命中→收招（**先看这张**）
- `pose_skeleton.mp4` —— 纯黑底骨架视频：只留火柴人轨迹，读肢体走向与两人相对站位最干净
- `pose_overlay.mp4` —— 骨架叠加原帧：对照原画面确认哪条肢体在出招
- `depth_*.mp4` —— 深度也出：判**出招肢体的前后**（哪只手/脚朝向镜头）
- `motion_heat.mp4` / `motion_edge.mp4` —— 打击轨迹、命中爆点、运镜（甩镜/命中推镜/环绕）

**读法**：`pose_strip`/`pose_skeleton` 读招式与站位、`depth` 读出招肢体前后、`motion_heat` 读打击轨迹与命中/运镜。参数：`--fps`（默认 8）、`--no-pose`（关骨架只留 edge/heat）、`--no-depth`（提速，只骨架+运动）、`--pose-model`（默认 `yolo11n-pose.pt`，可换 `yolo11s/m-pose.pt` 更准更慢）。

> **武打复刻的诚实边界**：反推可以得到打斗提示词和逐拍分镜，但生成式视频模型通常**不保证帧级精确连招复刻**。按“技法类别 + 节奏 + 运镜 + 氛围”描述，不要承诺逐帧对齐。

### 通用参数与降级

参数：`--mode auto|character|landscape|action`、`--fps`（character 4 / landscape 2 / action 8）、`--colormap all|gray|magma|turbo`、`--model`（深度模型，默认 Depth-Anything-V2-Small-hf，CPU 约 0.6s/帧）、`--py`（指定 python）、`--with-depth`（landscape 下强开深度）、`--no-depth`（任意模式跳深度提速）、`--no-pose` / `--pose-model`（action 骨架）。

> **降级**：无 Python/torch 时，character/auto/action 自动跳过真深度、仅出 ffmpeg 运动 pass（motion_edge + motion_heat）；无 ultralytics/opencv 时 action 跳过骨架、仍用 edge（轮廓读姿态）+ heat（轨迹）。装真深度：`pip install transformers timm pillow torch`；装骨架：`pip install ultralytics opencv-python`（均 CPU 版即可）。
> **合规**：运动理解产物仅用于理解运动与光色，绝不把原片人物抽帧/抽脸复用。原片演员生成新身份；若用户另行提供并明确指定替换人物，则使用该授权原照片作为唯一身份权威（见 replicate.md）。

## ④ 运镜判定（Claude 亲眼读 ②③ 帧）

结合 ② 的密集帧与 ③ 的深度/运动产物，逐段判定运镜，每条都要有帧证据（**人物片主看深度趋势，风景片主看 motion_heat 视差 + 原帧**）：

- **推/拉**：主体在画面里持续变大/变小；人物片深度整体变亮/变暗、风景片 motion_heat 近景视差骤增 → 推近 / 拉远。
- **摇/移（pan/track）**：背景横向或纵向连续位移，主体相对稳定 → 摇镜 / 平移 / 跟随（帧差热图上表现为整幅位移）。
- **升降/环绕**：地平线高度变化 / 主体侧面逐渐转出 → 升降臂 / 环绕（风景片看云海/建筑的视差方向）。
- **机位与景别**：人物片由深度层次判断景别与景深；风景片由原帧的近实远虚 + 构图判断。
- **武打片**：先用 `pose_strip`/`pose_skeleton` 逐拍拆招（蓄力→出招→命中→收招）、看两人相对站位与距离变化，再叠 `motion_heat` 判命中推镜/甩镜/环绕；**帧差在硬切与命中处会爆亮，别把命中闪光误判成运镜**。

单帧无法区分"推镜"还是"人物走近"——**必须看连续帧 + 运动趋势**共同定论。**风景 montage 片注意**：帧差在硬切处会假性爆亮，只在同一镜头内读运镜。判不准的运镜标"不确定"，不硬写。

## ⑤ 分镜头脚本（Claude）

把 ①–④ 的证据汇成一张分镜表（这是 shotlist.json 的人类可读版），每段一行：

```text
镜1  0–3秒  景别/机位  运镜  画面与主体动作(起→止)  声音  画面文字
镜2  3–8秒  ……
```

**证据分级铁律**（贯穿④⑤）：
- 每条观察分 `已确认`（帧证据）/ `推断`（合理但无直接证据，标注）/ `未知`（不写入）。
- **开头钩子完整盘点**：前 3 秒的前景动作、背景动作、运镜、画面文字、音乐节奏全部覆盖，不得只留主体动作。
- **画面文字**：准确内容、语言、颜色、位置、出现/持续时间、固定还是随物运动；辨不清标"不确定"。
- 同一卖点下多个快速硬切合并为一个分镜，但保留内部切换顺序。
- 用户纠正后：清空旧判断、重看原始帧与深度图，不得只给旧结论换说法。

## ⑥ 最终提示词（Claude）

**⚠️ 主角先行（强制）**：若反推识别到反复出现的核心人物/产品，先判身份来源。原片演员不得复用，生成合规新身份锚定图；用户另行提供并明确说“用这个人”时，原照片是唯一身份权威，每张关键帧用 `--identity-ref` 直接参考，视频用 `--identity-image` 继续直传，禁止 AI 锚定图套 AI 锚定图替代身份。

先列参考图上传顺序与各自职责（用户已提供、或上面新生成的锚定图），再输出一份可直接复制的四层提示词：

```text
【全局设定】视频参数、画面风格、核心运镜、整体声音分布（紧凑，只写生成所需）
【主体一致性】只锁定反复出现的核心人物/产品
【场景一致性】只锁定反复出现的核心场景
【文字】已确认的画面文字及其样式、位置、时间
【负面约束】只保留高风险项（主体漂移、文字乱码、钩子缺失）

0–3秒：镜头描写 / 画面与动作 / 声音
3–8秒：……
```

**⚠️ 先审核后落库（强制）**：反推出的最终提示词**必须先在对话里完整展示给用户审核**——把四层提示词与分镜表逐段贴出、说明每张参考图职责、标注不确定项（机型/台词/音效等），等用户确认或修订后**才**写入 `prompts/*.txt`、才进入出片。**严禁在用户看到并确认前"直接落库"或直接调 `image`/`video` 出片**——用户往往要改机型（如把"隐身战机"定为具体型号）、改台词、改节奏。展示时可同时给"整段版"和"分段版"两种供用户选。落库后若用户再修订，同步覆盖 `prompts/*.txt`，不留过期版本。

分镜时间用整数。交付前逐项核对：钩子每个成分已写入、运镜与④一致、动作方向与帧一致、每个音效有证据、每张参考图只有一个职责、人物已按身份路由正确绑定、授权真人 dry-run 已出现 `mode:"authorized-direct"`、最终提示词已在对话展示并获用户确认后才落库。

## ⑦ 音频拆解（audio 子命令：人声转写 + BGM描述 + 音效时间轴）

**为什么单列一段**：画面只讲了一半故事——台词、音效、BGM 情绪承载另一半。88API 当前没有可用的专用 STT 渠道，所以默认走 **Gemini 3.7 Flash 多模态**，一条命令拆出三样：

```powershell
node "<PLUGIN_ROOT>/scripts/studio.mjs" audio --video "<视频>" --out "<project>/analysis/audio"
# 只拆某段：加 --start 8 --end 16（秒）
# 直接给音频文件：--audio clip.mp3（跳过抽音）
# 默认模型：gemini-3.7-flash；只有用户明确同意时才用 --model 临时指定其它支持 input_audio 的模型
# 本地 Demucs 分人声/伴奏供人耳核对：--separate（缺 python/demucs 自动降级用整轨，不阻断）
```

产出 `audio_analysis.md`（同时存 `.json` 留原始响应）：
- **【一】人声台词转写**：逐句 + 大致时间戳；完全没有人声会明确写"无人声台词"；语言非中文标语种并给原文。
- **【二】BGM 描述**：风格类型 / 主要配器 / 情绪 / 大致 BPM / 随画面的情绪起伏时间线——**只描述、不逐字转录歌词、不提取原曲（版权）**。
- **【三】音效(SFX)时间轴**：可辨识音效（风声/爆破/脚步/金属撞击/低频 riser 等）按时间段列出。

**读法与诚实边界**：
- 时间戳是模型**估算、非帧级精准**（要词级精准得等 88api 挂上 whisper 渠道，那时 `audio` 可换 `--model whisper-1` 走转写端点）。
- **画面出现某动作 ≠ 存在对应音效**——只认报告里"确认听到"的声音；模型听不清会自己标"不确定"，别替它补全，也别把画面脑补成音效。
- 口播/台词最终仍**让用户确认或提供文案**；拿不准的台词保留"不确定"。
- 把这份三段时间轴和 **②的切镜点**、**⑤的分镜**逐段对齐，音画就能对上（哪一拍的音效/情绪属于哪个镜头）。
- **BGM 一律不提取、不复用**，只把风格描述写进 ⑥ 最终提示词的"整体声音分布"里（节奏/情绪/配器）。

## 收尾：直接复刻或转工程包

用户确认提示词后：
- **直接出片**：先刷新目录并让用户选择模型，再按“主角先行”分支执行。原片演员用新身份锚定图；授权替换人物的每张关键帧用 `--identity-ref`，视频继续用 `--identity-image`，并以 dry-run 身份审计为提交门槛。原片超过所选模型单段上限时按叙事段落拆分，最后 `concat`。
- **要可复刻工程包**（补素材、合规新身份、逐段绑定）：转 [replicate.md](replicate.md)。
