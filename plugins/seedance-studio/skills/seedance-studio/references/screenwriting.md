# 剧本审核铁律（T2 前置 · 免费）

在 T2 大项目里，剧本决定成败。生成一个镜头要花真钱，**在错的本子上生成 = 精准地浪费钱**。所以进入分镜与生成之前，先用这套铁律审一遍剧本：你不是替用户写剧本，而是质检员和参谋——指出具体问题、给改稿方向，本子不行就直说。

> 方法论改编自 Vi7QY/screenwriter-skill（MIT，头部短剧平台实战审稿标准），正文为本项目重写。

## 九条铁律

1. **无聊是最大的罪。** 没人为无聊付费。每一场都要问"观众为什么不划走"。
2. **第一集/前 15 秒决定生死。** 黄金开场必须立刻抛钩子；第一集不过关，后面全白费。
3. **风格先行。** 改稿前先定调性（热血/甜宠/虐恋/悬疑/复仇/搞笑），风格决定一切修改方向。
4. **诚实高于安慰。** 不行就说不行，别说"还不错但是…"这种废话。
5. **设定好 ≠ 写出来了。** 人设小传再漂亮，剧本里没体现就等于没有——审稿必须对照小传逐项核对是否落地。
6. **观众不想动脑。** 正反派黑白分明，关键信息前置交代，别指望观众自己推理。
7. **金手指必须贯穿。** 系统/重生/穿书类的"金手指"是全剧引擎，前三集说清，之后每个关键决策都要体现它在起作用。
8. **台词 > 内心独白。** 冲突用台词吵出来，别用旁白/OS 交代，观众想看冲突不想听念白。
9. **爽感必须兑现。** 设定里承诺的爽点（逆袭、打脸、变强、撩人）必须在剧本中逐项落地；承诺了没兑现 = 欺骗观众。

## 第一层：选题判断

用户给"名称 + 题材 + 梗概 + 人物小传"时，逐项判断并固定格式输出：

```
【选题判断】
调性：___
市场性：___（对标爆款：___）
人设讨喜度：___（有无劝退设定）
目标用户：男频/女频，画像 ___
钩子潜力：从梗概能看到几个天然冲突/情绪爆点 ___
综合判断：✅ 值得做 / ⚠️ 需调方向 / ❌ 不建议做
选题评级：S/A/B/C（只评选题天花板，≠剧本质量）
理由：___
```

## 第二层：第一集生死线

拿到第一集（或前三集）剧本时逐项检查：
- **开场钩子**：前 15 秒有没有立刻抓人的冲突/悬念/反差？没有 → 直接标红。
- **信息前置**：主角身份、金手指、核心矛盾是否在开头交代清楚，还是拖沓铺垫？
- **爽点节奏**：情绪爆点是否密集且逐个兑现？有没有"承诺了却没打脸/没逆袭"的空头支票？
- **人设落地**：小传里的性格、金手指、卖点，剧本里逐项对照——哪些写出来了，哪些只停在设定。
- **台词冲突**：关键对抗是用台词吵出来的，还是用旁白糊弄过去？

## 输出：改稿方向而非替写

审完给三样，不替用户写剧本：
1. **问题清单**（具体到场/句，标严重度：致命 / 待改 / 建议）；
2. **改稿方向**（先定风格，再给结构级建议，不逐句代笔）；
3. **是否放行进入分镜**：通过 → 进 [production.md](production.md) 阶段 2；不通过 → 指明必须先修的致命项。

## 与生成阶段的接口

审核通过的剧本落盘为 `scripts/epNN.md`，其分集大纲、人设小传、金手指设定，直接喂给 production.md 阶段 2（分镜）与阶段 3（角色 bible / 设定图）。人设小传里的固定外观描述（脸/发/身材/服装配色）应逐字进入 `characters/bible.json`，成为跨集一致性的文字基准。
